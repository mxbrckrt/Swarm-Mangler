Chapter 01

System Overview & Design Philosophy

Swarm-Mangler bridges high-density polyphonic sample manipulation with sample-accurate multichannel spatial choreography and low-latency 3D telemetry.

In contemporary electroacoustic, acousmatic, and spatial music, sound diffusion is rarely static. The acoustic identity of a sound object is defined not merely by its spectral envelope, but by its kinetic velocity, spatial dispersion, and inter-loudspeaker decorrelation. Swarm-Mangler treats space as an expressive, ballistic dimension synchronized with microtonal transposition, time-stretching, and dynamic clouds.

⚡

32-Voice Parallel Engine

Powered by [mcs.poly~ player-core 32], providing independent varispeed pitch ramps, phase-vocoder time stretching, dynamic amplitude shaping, and ballistic spatialization per voice.

🌌

Ballistic Spatial Engine

Combines non-linear ease-in trajectory generators (whiplash.gendsp) with high-contrast equal-power cosine beam forming and distance-based air absorption (adm_panner.gendsp).

🎶

Harmonic Modal Quantizer

Constrains random pitch shifts to microtonal and historical modal scales (Risset inharmonic bell, Messiaen modes, Xenakis sieves, Debussy, Ligeti clusters) with discrete octave bounds.

🔄

32×64 Paged Matrix

A static 16×16 viewport visual router (matrix_32x64.js) addressing up to 64 physical Dante/DAC outputs with 1-click diagonal patching, channel locks, and pattr storage.

🌊

Multichannel FDN Reverb

Unitary Hadamard 4-delay Feedback Delay Network (fdn_multireverb.gendsp) with rotating multi-phase circular LFO modulation and golden-ratio prime detuning per channel.

📡

Real-Time 3D WebGL Telemetry

Atomic sample-accurate /adm/obj/<id>/xyz telemetry paired with an autonomous Three.js monitor (visionOS glass style) supporting live CSV/XLSX speaker layout drag & drop.

Chapter 02

Quick Start Tutorial

Follow these 6 essential steps to load soundfiles, configure routing, launch the 3D monitor, and fire your first spatial sound swarm.

  1. Step 1: Load Audio Files into the Pool
    In the -polybuffer- module, click "Load soundfiles" or drag-and-drop a folder of audio files (WAV, AIFF, FLAC) directly from Finder onto the drop zone. The total file count will update immediately.
  2. Step 2: Define Active Loudspeaker Channels
    In the main patcher header, adjust the n° of channels number box (e.g., 6 for hexagonal studio setups, 28 for concert domes). This locks all unused matrix columns and configures both the ADM panner and FDN reverb.
  3. Step 3: Connect Matrix Routing to Physical Outputs
    Open the output matrix patch. Click the diagonal button to automatically establish a 1:1 patch ($1\rightarrow 1, 2\rightarrow 2 \dots$) up to the current active channel count, or patch custom crosspoints manually.
  4. Step 4: Launch the 3D WebGL Monitor
    Open swarm_mangler_3d_spatial_viewer.html in Google Chrome. Drag & drop your loudspeaker configuration file (e.g., gramestudio-speaker-setup.csv or maxBstudio-speaker-setup.csv) directly onto the lower-left drop zone. The speaker array appears immediately, normalized to the virtual hall boundaries.
  5. Step 5: Choose a Playback Mode & Modulation
    Set Playback mode to Varispeed ON. Set glissandis-durations to 500 ms, min pitch to 0.8, and max pitch to 1.5. Enable Rndm pitch ON to explore modal scales (e.g., risset_InharmonicBell). Set is3D to 0 (planar $Z=0.5$ median ear level) or 1 (full 3D volumetric trajectories).
  6. Step 6: Trigger Sounds & Launch a Cloud
    Click trig one file to hear and see a single ballistic spatial event. Then set interval to 120 ms, jitter to 50%, occurrences to 16, and click start arpeggio to launch an immersive kinetic swarm.
💡 Pro-Tip: Selective Panic & Scene Purge

If soundfiles ring or repeat too long, press the "stop all" button. The master engine applies a selective pop-free fade-out (stopDur) to active voices. Furthermore, clicking "Clear Sources" in the 3D monitor or sending /clearsources instantly extinguishes any remaining visual sources without disrupting the audio DSP.

Chapter 04

Polybuffer & File Handling Engine

Autonomous sample caching with genuine filesystem name tracking and equal-power downmix normalization.

1. Genuine Soundfile Name Resolution

Standard Max [polybuffer~] objects assign generic internal identifiers (e.g., my-sfiles.1, my-sfiles.2). Swarm-Mangler intercepts the internal dump stream using the shortname <idx> <name> protocol in master_engine.js. This guarantees:

  • Internal audio DSP queries reference the exact buffer symbol (e.g. my-sfiles.14).
  • The visual telemetry dashboard (poly_monitor.js) displays the authentic soundfile name on disk (e.g. bamboo_strike_03.wav).

2. Equal-Power Mono Downmix Normalization

Audio files dropped into the buffer pool may be mono or stereo. Inside each player-core voice, the channel count is dynamically queried:

  • Mono files: Channel 1 is passed directly at unity gain ($1.0$).
  • Stereo files: Left and Right channels are summed and multiplied by $\frac{1}{\sqrt{2}} \approx 0.7071$ ($-3\text{ dB}$).

This acoustic power compensation guarantees that stereo soundfiles do not overpower mono files or saturate the spatializer input stage.

Chapter 05

Playback Modes & Pitch Transposition

Three distinct pitch execution modes with integral duration compensation.

Mode Comparison

Mode Index Mode Name Description Dynamic Controls
mode 0 Straight (Original) Plays buffer at natural speed ($1.0$). Duration equals original buffer length. Attack %, Decay %, Amplitude dB
mode 1 Varispeed / Random Ramp Linear speed interpolation between transpoMin and transpoMax over transpoDur. transpoMin, transpoMax, transpoDur, transpoProba, transpoStable
mode 2 Curve Envelope (BPF) Varispeed driven by a custom breakpoint curve lookup table (pitchcurve). Presets (init, dive, riser, random), Time-stretch toggle

Integral Duration Compensation Mechanics

When a soundfile is played at a fluctuating varispeed speed ramp from $v_{\text{start}}$ to $v_{\text{end}}$ over ramp duration $T_{\text{ramp}}$, the physical audio buffer is consumed at a non-linear rate: 

bufferConsumed = T_ramp * ((v_start + v_end) / 2.0)

If the entire buffer is consumed before the ramp completes, master_engine.js solves the quadratic kinematic motion equation: 

delta = v_start^2 + 2 * a * buffer_duration
effectiveDuration = (sqrt(delta) - v_start) / a

This sample-accurate compensation guarantees that the amplitude envelope generator (zigzag~) terminates in exact synchrony with the end of the soundfile, completely eliminating clicks or hanging voices.

Harmonic Modal Scale Quantizer

Lock random pitch transpositions to historical microtonal, spectral, and modern harmonic scales.

When Rndm pitch ON (harmonicMode 1) is activated, random pitch selections in Mode 1 are no longer drawn as continuous floating-point ratios. Instead, speeds are quantized to exact 12-TET interval ratios ($2^{\frac{\text{semitone}}{12}}$) drawn randomly from harmony_presets.json.

🎼 Discrete Octave Bounds

In this mode, transpoMin and transpoMax represent integer octave multipliers:
octaveShift = round(log2(transpo)).
A modal pitch degree is randomly selected from the scale and multiplied by $2^k$ octaves.

Triggers & Stochastic Cloud Engine

Deterministic and Poisson-distributed kinetic gesture generation.

Swarm-Mangler supports three independent trigger methodologies:

1. Manual One-Shot

Clicking the trig one file button (or receiving a message on r -external-oneshot-) immediately dequeues the next soundfile according to the active playMode:

  • Mode 0 (Round-Robin / Urn Random): Permutates through all loaded buffers without repetition until the pool is exhausted, then automatically reshuffles.
  • Mode 1 (Forward / Sequential Loop): Advances sequentially ($0, 1, 2, \dots N-1, 0, 1\dots$) through loaded files.

2. Stochastic Cloud Generator (stochastic-cloud.gendsp)

Designed for dense acoustic swarm textures and granular arpeggios:

Parameter Range Description
interval $10 \dots 5000\text{ ms}$ Base temporal spacing between successive triggers.
jitter $0 \dots 100\%$ Stochastic Poisson timing displacement factor.
occurrences $1 \dots 128$ Total number of bursts emitted in the arpeggio sequence.
loop 0 | 1 Toggles endless continuous swarm emission vs. finite burst.

Chapter 09

Ballistic ADM Spatialization Engine

Kinetic acousmatic sound projection with dynamic atmospheric air absorption.

1. Coordinate Space Conventions

Swarm-Mangler adheres strictly to Cartesian Audio Definition Model (ADM / ITU-R BS.2076) standards:

X (Azimuth Axis)

Range: $[-1.0 \dots +1.0]$
Left: $-1.0$ • Center: $0.0$ • Right: $+1.0$

Y (Depth Axis)

Range: $[-1.0 \dots +1.0]$
Back: $-1.0$ • Center: $0.0$ • Front: $+1.0$

Z (Elevation Axis)

Range: $[0.0 \dots 1.0]$
Floor: $0.0$ • Median Ear Level: $0.5$ • Zenith/Ceiling: $1.0$

📏 2D vs 3D Elevation Handling (is3D)

In standard horizontal ring diffusion (is3D 0), the elevation coordinate $Z$ is strictly locked to $0.5$ (the geometric median horizontal listening plane of the virtual hall). When is3D 1 is enabled, autonomous random trajectories span the entire volume $[0.0 \dots 1.0]$.

2. Ballistic Trajectory Generator (whiplash.gendsp)

The whiplash.gendsp module applies a composite non-linear curve blending $80\%$ exponential ease-in curvature with $20\%$ linear momentum: 

p_lin = clip(current_sample / total_samples, 0.0, 1.0)
p_curved = (p_lin * 0.2) + (pow(p_lin, curve) * 0.8)
pos = start_val + (end_val - start_val) * p_curved

The curve parameter ($1.0 \dots 6.0$) adjusts the gesture: at $1.0$, the trajectory is linear; at $3.0$, it produces a sharp, whipping snap into the destination coordinate.
  
3. High-Contrast ADM Panner (adm_panner.gendsp)

  

    Operating within [mc.gen~ adm_panner], each loudspeaker channel evaluates its own gain law based on shortest angular distance $\Delta\theta$:
  

  
beam_limit = (2.0 / speakers) * width_norm
gain = pow(cos((dist / beam_limit) * (PI * 0.5)), sharpness)  
4. Atmospheric Air Absorption Damping (ISO 9613-1)

  

    As radial distance $d = \sqrt{x^2 + y^2}$ increases, a real-time one-pole lowpass filter progressively rolls off high frequencies from $20\text{ kHz}$ down to $2.5\text{ kHz}$ based on the air_damp parameter.

Chapter 10

3D OSC Telemetry & Autonomous WebGL Monitor

Atomic sample-accurate OSC streaming paired with a standalone 3D Three.js spatial monitor.

1. Sample-Accurate OSC Latching

Inside each player-core voice, 3D_snapshot_sync_polyvoice.gendsp latches $X, Y, Z$ trajectory coordinates on atomic single-sample boundaries, streaming UDP OSC packets: 

/adm/obj/<voiceID>/xyz <xFloat> <yFloat> <zFloat>

Packets are transmitted over UDP to external spatial renderers (Dolby Atmos, SPAT, L-ISA) and bridged to WebSockets (port 8080) for the companion HTML5 interface.

2. The Standalone 3D Spatial Viewer (swarm_mangler_3d_spatial_viewer.html)

The browser-based monitor provides an intuitive, high-performance 3D visualization styled with modern glassmorphism (visionOS style), optimized for low-end GPUs:

Direct CSV/XLSX Ingestion

Drag & drop real speaker layouts (e.g., Grame 28-speaker dome or private studio rings). Supports European semicolons (;) and comma decimals seamlessly.

Real-Room Proportional Normalization

Automatically calculates radial hall boundaries. Furthest speakers snap to the walls ($\pm 0.92$), and single-height rings map to the virtual hall median ($Y=0.50$).

Amber Glass Visuals

Sources render as translucent amber physical glass spheres with centered high-contrast IDs, grounded drop-shadows, and vertical plumb lines.

Anti-Jitter Spawn Masking

An internal $8\text{ ms}$ hold-off mask absorbs residual packet jitter upon voice triggering, guaranteeing smooth trajectory starts without initial jump artifacts.

3. Global Scene Purge (/clearsources)

To prevent visual voice artifacts when sequences are stopped or interrupted in Max, the monitor supports an immediate cleanup routine:

  • Triggered manually via the on-screen "Clear Sources" button.
  • Triggered remotely by sending the OSC message /clearsources or /clear directly from Max.

Multichannel Spatial FDN Reverb (fdn_multireverb.gendsp)

Lush Feedback Delay Network with orthogonal Hadamard matrixing and rotational chorus.

The reverb engine (fdn_multireverb.gendsp) is implemented in GenExpr and natively wrapped in [mc.gen~] to process $N$ discrete channels simultaneously:

Parameter Range Default Acoustic Role
size $0.5 \dots 100$ 90.0 Perceived acoustic room dimensions and base delay lengths.
decay $0 \dots 110$ 82.0 Feedback gain ($100 = \text{infinite self-oscillation threshold}$).
spread $0 \dots 100$ 90.0 Inter-channel spatial decorrelation & multiphase rotation depth.
absorb $0 \dots 100$ 10.0 High-frequency damping absorption inside the feedback matrix.
tilt $-1.0 \dots +1.0$ -0.1 Spectral balance filter ($-1.0 = \text{dark/warm}$, $+1.0 = \text{bright/shimmer}$).
predelay $0 \dots 100\text{ ms}$ 10.0 Pre-delay buffer time before entering all-pass diffusion.
speed $0.1 \dots 10\text{ Hz}$ 1.0 Rotational LFO modulation rate around the speaker ring.
depth $0 \dots 20$ 5.0 Pitch modulation / chorus shimmer depth.
mix $0 \dots 100\%$ 25.0 Dry / Wet balance control.
💡 Non-Commensurate Prime Detuning

Each loudspeaker channel receives delay lines subtly detuned via the Golden Ratio:
ch_detune = sin((ch_idx + 1) * 1.6180339887) * 0.06 * spread.
This completely prevents inter-speaker comb filtering and eliminates standing room nodes.

Chapter 14

Selective Voice Panic System

Intelligent voice termination without clicks or global DSP interruption.

Traditional panic buttons abruptly mute entire polyphonic clusters, causing harsh audio clicks and DSP spikes. Swarm-Mangler implements a Selective Panic Registry:

  1. activeVoicesRegistry tracks exact expiration timestamps of currently running voices.
  2. When panic is triggered, the engine emits target <voiceID> and panic <stopDur> commands exclusively to running voices.
  3. Idle voices remain completely untouched, keeping DSP load minimal.
  4. Inside player-core, a smooth non-linear fade-out envelope is executed over stopDur milliseconds (default $100\text{ ms}$).
